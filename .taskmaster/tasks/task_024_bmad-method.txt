# Description: Implement a comprehensive pre-merge approval checklist for the Auth/Prisma refactoring, ensuring all security, functionality, and quality standards are met before merging into the main branch.
# Details:
This task involves creating and executing a detailed checklist to validate the refactored authentication system integrated with Prisma before allowing the merge. Key components include: 1) Automated Testing: Ensure all unit and integration tests pass, with a minimum code coverage threshold (e.g., 80%) using tools like Jest or Mocha. 2) Manual Validation: Perform manual checks against acceptance criteria, such as successful login/logout flows, role-based access control for Compradora, Fiscal, Aprovadores, and Fornecedores, and proper handling of refresh tokens. 3) Prisma Migrations and Rollback: Verify that database migrations run successfully, data integrity is maintained, and rollback procedures are in place and tested to prevent data loss. 4) Protected Routes Validation: Test all protected endpoints to confirm JWT validation, middleware enforcement, and unauthorized access blocking. 5) Security Review: Conduct a thorough audit of JWT token handling (issuance, validation, expiration), secure cookie settings (httpOnly, secure flags), header validation, rate limiting implementation (e.g., using express-rate-limit), and overall vulnerability checks using tools like OWASP ZAP or manual code review. 6) Observability Checklist: Ensure comprehensive logging (e.g., using Winston or Pino) for authentication events, errors, and security incidents, and set up metrics (e.g., via Prometheus) for monitoring login attempts, failures, token usage, and performance. The checklist should be documented in a template (e.g., Markdown file) and automated where possible via CI/CD pipelines (e.g., GitHub Actions) to block merges if criteria are not met. Consider integrating with tools like SonarQube for code quality and security scans.
