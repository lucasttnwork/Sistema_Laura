# Test Strategy:
Test login/logout flows, verify JWT tokens are issued and validated correctly, check role-based access to protected routes.

# Subtasks:
## 1. Set up JWT and refresh token infrastructure [done]
### Dependencies: None
### Description: Configure Express.js with JWT library to issue and verify access and refresh tokens for all user roles.
### Details:
Use jsonwebtoken and express-jwt libraries. Define token expiration times and secret keys. Structure token payloads to include user ID and role.

## 2. Implement authentication middleware and role-based access control [pending]
### Dependencies: 2.1
### Description: Create middleware to validate JWTs and enforce role-based permissions on protected routes.
### Details:
Middleware should extract user role from token and compare against route permissions. Return 403 for unauthorized access.

## 3. Build user registration, login, and logout endpoints [pending]
### Dependencies: 2.1
### Description: Develop API endpoints for user registration, login (issuing tokens), and logout (invalidating refresh tokens).
### Details:
Hash passwords using bcrypt. Validate inputs with Zod. Store refresh tokens in Supabase. Logout should blacklist or delete refresh tokens.

## 4. Integrate Supabase for production authentication and user management [pending]
### Dependencies: 2.3
### Description: Connect authentication system to Supabase for user storage, session management, and secure credential handling in production.
### Details:
Use Supabase Auth hooks or client SDK. Sync user roles and metadata. Ensure environment-specific configs for dev vs prod.

## 5. Implement secure frontend token storage using Zustand [pending]
### Dependencies: 2.1, 2.3
### Description: Manage authentication state on the frontend using Zustand, ensuring tokens are stored securely and accessible across components.
### Details:
Store only access token in memory or httpOnly cookies if possible. Use Zustand for global auth state (isLoggedIn, userRole). Clear state on logout.

## 6. Refatorar Auth para Prisma (User + RefreshToken) — Opção B [pending]
### Dependencies: 23, 24
### Description: Refatorar backend para usar Prisma com modelos `User` e `RefreshToken`, mantendo JWT + refresh. Migrar fluxo de login/refresh/logout e middlewares para persistência via Prisma.
### Details:
Critérios de aceite:
- login/refresh/logout funcionando
- tokens salvos em tabela RefreshToken
- senha em campo dedicado (hash Bcrypt)
- rota protegida respondendo 200 com Authorization: Bearer <token>
Implementação mínima:
- Prisma models: User(id,email,passwordHash,roles,...), RefreshToken(id,userId,token,expiresAt,revokedAt)
- Endpoints: POST /auth/login, POST /auth/refresh, POST /auth/logout, GET /protected (exemplo)
- Middleware: validação Bearer, injeção de user no request
- Revogação/rotação de refresh token
- Testes de fumaça cobrindo os critérios
