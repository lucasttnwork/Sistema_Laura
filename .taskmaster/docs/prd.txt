# SISTEMA LAURA - PRD (Product Requirements Document)
## Sistema de Gestão de Compras e Materiais para Construção Civil

### 🎯 **VISÃO GERAL**

O Sistema Laura é uma plataforma digital completa para gestão de procurement em obras de construção civil. O sistema centraliza todas as operações de compras, desde a solicitação de materiais até a aprovação de cotações, com integração nativa ao WhatsApp para comunicação eficiente com fornecedores.

### 📋 **OBJETIVOS DO SISTEMA**

#### Objetivo Principal
- **Centralizar e automatizar** todo o processo de procurement em obras de construção civil
- **Eliminar processos manuais** de solicitação, cotação e aprovação de materiais
- **Integrar comunicação** com fornecedores via WhatsApp
- **Garantir rastreabilidade** completa de todas as operações
- **Fornecer dashboards** em tempo real para acompanhamento de processos

#### Objetivos Específicos
1. **Gestão de Solicitações**: Interface intuitiva para solicitação de materiais por obra
2. **Cotação Automatizada**: Sistema inteligente de distribuição de cotações para fornecedores
3. **Aprovação Hierárquica**: Workflow de aprovações baseado em valores e regras de negócio
4. **Integração WhatsApp**: Comunicação nativa com fornecedores via WhatsApp Business API
5. **Dashboard Executivo**: Visão consolidada de todas as operações
6. **Rastreabilidade Completa**: Histórico detalhado de todas as ações e decisões
7. **Gestão de Fornecedores**: Cadastro e classificação de fornecedores por categoria
8. **Controle de Arquivos**: Sistema de anexos para cotações, especificações e contratos

### 👥 **PERSONAS E USUÁRIOS**

- **Necessidades**:

  - Visualizar histórico de materiais por obra

#### 3. **Aprovadores (Gerentes/Diretoria)**
- **Perfil**: Gestores responsáveis por aprovar compras
- **Necessidades**:

- Cadastro completo de fornecedores

- Integração WhatsApp automática

#### **Módulo 4: Sistema de Cotação**
- Distribuição automática de cotações por categoria
- Controle de prazos de resposta
- Recebimento de propostas via WhatsApp
- Validação automática de formatos
- Comparativo automático de preços

#### **Módulo 5: Workflow de Aprovação**
- Regras configuráveis por valor
- Aprovação hierárquica automática
- Notificações em tempo real
- Histórico completo de decisões
- Justificativas obrigatórias para reprovações

#### **Módulo 6: Dashboards e Relatórios**
- Dashboard executivo com métricas principais
- Relatórios por obra, fornecedor e período
- Gráficos de performance de fornecedores
- Análise de custos por categoria
- Exportação para Excel/PDF

#### **Módulo 7: Integração WhatsApp**
- Conexão com WhatsApp Business API
- Templates de mensagens automatizadas
- Recebimento de mensagens de fornecedores
- Processamento automático de propostas
- Notificações de status via WhatsApp

### 🏗️ **ARQUITETURA TÉCNICA**

#### **Frontend (Dashboard)**
- **Framework**: React com TypeScript
- **UI Library**: Shadcn/ui + Tailwind CSS
- **Estado**: Zustand para gerenciamento de estado
- **Roteamento**: React Router
- **API Client**: Axios com interceptors

#### **Backend (API)**
- **Framework**: Express.js com TypeScript
- **Autenticação**: JWT com refresh tokens
- **Validação**: Zod para schemas
- **Documentação**: Swagger/OpenAPI
- **Logs**: Winston estruturado

#### **Banco de Dados**
- **Local/Desenvolvimento**: PostgreSQL via Docker
- **Produção**: Supabase (PostgreSQL managed)
- **ORM**: Prisma com migrations
- **Cache**: Redis para sessões e cache

#### **Integrações**
- **WhatsApp**: Z-API ou 360Dialog
- **Storage**: Supabase Storage para arquivos
- **Email**: SendGrid ou similar
- **Notificações**: Push notifications

### 📊 **REQUISITOS FUNCIONAIS**

#### **RF001: Cadastro de Solicitações**
- O sistema deve permitir criar solicitações de materiais
- Cada solicitação deve estar vinculada a uma obra
- Deve ser possível anexar especificações técnicas
- Status inicial deve ser "Pendente"

#### **RF002: Distribuição de Cotações**
- Sistema deve identificar fornecedores por categoria
- Deve enviar cotação para no mínimo 3 fornecedores
- Prazo padrão de 24h para resposta
- Notificação automática via WhatsApp

#### **RF003: Recebimento de Propostas**
- Fornecedor pode responder via WhatsApp
- Sistema deve parsear automaticamente valor, prazo e condições
- Validação de formato das propostas
- Confirmação automática de recebimento

#### **RF004: Análise Comparativa**
- Interface para comparar todas as propostas recebidas
- Destaque automático da melhor proposta
- Cálculo de economia potencial
- Filtros por fornecedor, valor, prazo

#### **RF005: Workflow de Aprovação**
- Regras baseadas em valor da compra
- Até R$ 5.000: Aprovação automática
- R$ 5.000 a R$ 50.000: Aprovação do fiscal
- Acima de R$ 50.000: Aprovação da diretoria
- Notificações automáticas

#### **RF006: Dashboard Executivo**
- Métricas em tempo real
- Gráficos de solicitações por status
- Top fornecedores por volume
- Análise de economia gerada

### ⚠️ **RISCOS E MITIGAÇÕES**

#### **Riscos Técnicos**
1. **Complexidade da Integração WhatsApp**
   - **Descrição**: Integração com WhatsApp Business API pode apresentar desafios de configuração e manutenção
   - **Impacto**: Alto - Pode atrasar desenvolvimento do módulo de cotações
   - **Probabilidade**: Média
   - **Mitigação**: Prototipar integração no início, ter plano B (SMS/email), documentar processo detalhadamente

2. **Performance com Alto Volume**
   - **Descrição**: Sistema pode enfrentar lentidão com grande volume de cotações simultâneas
   - **Impacto**: Alto - Afeta experiência do usuário em momentos críticos
   - **Probabilidade**: Baixa-Média
   - **Mitigação**: Implementar cache Redis desde o início, otimizar queries, realizar testes de carga

3. **Dependências de Terceiros**
   - **Descrição**: Supabase, WhatsApp API e outros serviços externos podem ter indisponibilidade
   - **Impacto**: Médio-Alto
   - **Probabilidade**: Baixa
   - **Mitigação**: Contratos SLA adequados, circuit breakers, plano de contingência

#### **Riscos de Projeto**
1. **Complexidade do Workflow de Aprovações**
   - **Descrição**: Regras hierárquicas complexas podem ser difíceis de implementar e manter
   - **Impacto**: Médio
   - **Probabilidade**: Média
   - **Mitigação**: Validar regras com stakeholders, prototipar workflow, documentar cenários

2. **Adoção pelos Usuários**
   - **Descrição**: Resistência à mudança por parte da equipe de procurement
   - **Impacto**: Alto
   - **Probabilidade**: Baixa-Média
   - **Mitigação**: Treinamentos, entregas incrementais, feedback contínuo

#### **Riscos de Negócio**
1. **Regulamentações Fiscais**
   - **Descrição**: Mudanças em legislação podem impactar funcionalidades de aprovação
   - **Impacto**: Alto
   - **Probabilidade**: Baixa
   - **Mitigação**: Consultoria jurídica, arquitetura flexível para ajustes

2. **Concorrência de Mercado**
   - **Descrição**: Outros sistemas similares podem surgir durante desenvolvimento
   - **Impacto**: Médio
   - **Probabilidade**: Baixa
   - **Mitigação**: Foco em diferenciais (WhatsApp, automação), entregas rápidas
